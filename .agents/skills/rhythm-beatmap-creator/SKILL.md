# 리듬 비트맵 크리에이터 (Rhythm Beatmap Creator)

## 목표
개발자가 새로운 음원 파일(MP3)을 `/public/music/` 디렉토리에 업로드한 뒤 당신을 호출하면, 당신은 곡의 특징을 분석(또는 추론)하여 가장 어울리는 게임 테마, BPM 및 난이도를 결정하고 게임 내에서 직접 플레이 가능한 비트맵(Beatmap, 노트 배치의 배열) 코드 및 UI 연동 코드를 자동으로 생성합니다.

## 사용 방법 (트리거)
사용자가 다음과 유사한 요청을 할 때 이 스킬이 자동으로 개입합니다.
- "새로운 곡 <곡이름>을 추가했어. 이 곡의 게임 화면과 노트 배치를 생성해줘."
- "수익화 전용 스테이지를 만들 거야. 새로운 MP3를 기반으로 비트맵과 UI 메타를 세팅해줘."

## 수행 지침 (에이전트 워크플로우)
새로운 곡 추가 요청을 받으면 아래 순서대로 작업을 수행하십시오:

**1. 곡 메타데이터 정의**
- 곡의 이름, 길이, 분위기에 어울리는 아티스트명(또는 제공된 이름), 기본 BPM(필요시 추론), 적정 난이도 수준(1~5)을 정의합니다.

**2. TitleScreen 곡 목록(AVAILABLE_SONGS) 업데이트**
- `src/components/TitleScreen/TitleScreen.tsx` (또는 상태 스토어) 내부에 정의된 곡 리스트 배열을 수정하여 새로운 곡 항목을 추가합니다.
- 예: 
  ```typescript
  {
      id: '새로운-음원-id',
      title: '새로운 곡 제목',
      artist: '아티스트',
      duration: '3:45',
      bpm: 140,
      difficulty: 4,
      url: '/music/new_song.mp3'
  }
  ```

**3. 구간별 생성 규칙(Procedural Script) 모듈 작성 (핵심!)**
- ⚠ **[중요]** Token Limit 및 성능 문제를 피하기 위해, 수백 개의 노트를 하드코딩(`{time: 1.2, lane: 0}`)하는 방식은 **절대 사용하지 마십시오.**
- 대신 해당 곡을 여러 **구간(Segment)**으로 나누어, 클라이언트가 런타임에 동적으로 노트를 파싱할 수 있는 **구조적 스크립트 기반 모듈**을 `src/game/charts/새로운_음원.ts` 위치에 생성하십시오.
- **예시 아키텍처 (구간별 규칙 배열):**
  ```typescript
  import { ChartSegment } from '../types' // (또는 직접 타입 선언)

  export const newSongChartScript: ChartSegment[] = [
      {
          startTime: 0,
          endTime: 30,
          phrase: 'Intro',
          density: 0.4,       // 밀도 (0~1)
          patterns: ['4비트 정박', '단일 노트 위주', 'D와 K 주로 사용'] 
      },
      {
          startTime: 30,
          endTime: 90,
          phrase: 'Build-up',
          density: 0.7,
          patterns: ['8비트 엇박 추가', '계단형 패턴', 'F, J 빈도 증가']
      },
      {
          startTime: 90,
          endTime: 120,
          phrase: 'Drop (Climax)',
          density: 1.0,
          patterns: ['16비트 연타', '동시치기(다중 노트) 포함', '가장 어려운 패턴']
      },
      // ... 곡 끝까지 반복
  ]
  ```
- 이처럼 **[시작 시간, 종료 시간, 페이즈 성격, 밀도, 패턴 설명]** 등의 구간 정보를 기획하면, 메인 게임 엔진(`generateNoteChart` 유사 함수)이 런타임에 이 규칙을 읽어 실제 `Note[]` 배열로 변환하도록 설계해야 합니다 (이 기능을 구현할 코드가 아직 없다면 Agent가 함께 스크립트 파싱(해석) 로직도 작성해 줘야 합니다).

**4. 곡 맞춤형 비주얼 테마 정의 (선택)**
- 만약 해당 곡이 특별한 유료/프리미엄 곡이라면(향후 수익화 기능 고려), 게임 렌더링 시 전용 배경 효과나 Visualizer 투명도/색상(`src/components/GameScreen/Visualizer.tsx` 참조) 값이 다르게 적용되도록 GameStore 상태에 테마(Theme) 속성을 주입할 수 있도록 코드를 확장합니다.

## 주의 사항
- 비트맵 설계 시 가장 중요한 것은 **사용자가 재미를 느끼는 '박자감'과 '가시성'**입니다. 
- 난이도가 높은 곡일 경우 노트가 짧은 시간에 집중되도록 처리하지만, 너무 무작위(Random)로 겹치게 설계하면 불쾌감이 생깁니다. '노트 패턴'은 사람이 칠 수 있도록 설계되어야 합니다.
- 개발 환경(관리자 모드)에서 요청될 시에만 구조 변경을 허용하고 게임이 런타임 오류로 무너지지 않는 안정적인 구조로 코드를 삽입하십시오.
